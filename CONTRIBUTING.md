# Contributing

Start with [the README](README.md) and choose one question or resource connection to improve.

Useful contributions include clearer writing, direct sources, evidence of outcomes, counterexamples, documented experiments and beginner pathways. Ordinary Markdown keeps the documentation readable without a build system.

For resource additions, use [the assessment template](templates/resource-assessment.md), link the assessment from [the resource map](docs/resources/README.md), and explain its connection to the architecture. Distinguish an organisation’s own account from independent evaluation.

For conceptual changes, explain which problem the change solves, what it assumes and what evidence could change our view. Record unresolved disagreements rather than making the text sound more certain than the evidence allows.

Use a branch and a pull request when hosted, or send a patch. Check local links before committing. Keep private conversations and participant information out of the repository.

This is an exploratory project. Contributions need not endorse every idea here. Licensing and formal project governance are still open decisions.
